# 节点：implement（PIV 执行体）

逐任务执行 plan：Prime→Implement→Validate 循环的最内层执行者。

## 输入（只读）

- `$ISSUE_DIR/plan.json`（plan 已吸收 issue 评论中的整改要求；
  若任务与 `$ISSUE_DIR/issue.json` 评论冲突，停止并声明 blocked）
- `$ISSUE_DIR/ralph-todo.md`（若存在且非空 = 修复轮：上一轮 review
  回流的可行动发现清单，见「修复轮」节；首轮不存在）
- `$ISSUE_DIR/salvage-r*.patch`（若存在 = 上轮失败链的**未提交**工作快照：
  只作证据——上轮做到哪、什么思路；**不是续作指令**，不自动 apply，
  有效改动只由本轮 plan.json 决定）

## 纪律（违反任何一条 = 本节点失败）

1. 每完成一个任务，立即运行其 `verify` 命令；失败就地修复后再进下一任务
2. 需要 touches 周界路径（MISSION.md 的 PERIMETER 清单）的任务：**跳过并在
   日志中标记 blocked**，绝不尝试修改、绕过或说服自己"这次不算"
3. 复用既有模式；不新增第三方依赖；不重构与本 issue 无关的代码
4. 全部任务后运行 `final_gate`（命令见任务参数「仓库参数」段），
   将完整输出另存到 `$ISSUE_DIR/tests-output.txt`（holdout 节点的输入）。
   随后对**触及的测试套件**以 `-v` 冗长模式重跑一次并附于该文件末尾：
   holdout 只见此文件且不允许推测，静默点号输出无法建立测试与诉求的
   对应关系（证据饥饿），测试名与参数化用例名是必需证据。
   若本次改动**新写了测试或针对性验证**（新增测试文件、新用例、独立验证
   脚本），其 `-v` 输出必须**逐条追加**进 tests-output.txt，标注所属文件与
   断言目标——holdout 以「issue 诉求 → 测试名」反向核对，新证据不落此
   文件 = 诉求无对应证据 = 判 FAIL（历史教训：2026-09-03 #123 r3 implement
   全绿但 tests-output.txt 只有预存套件，新诉求零证据，holdout FAIL）
5. 完成后把改动提交到当前分支（不 push、不开 PR——那是链脚本的事）
6. **预算纪律**：本节点受编排器硬性时间预算击杀（--max-time，任务参数段
   有具体值）。预算过半仍未进入最后一个任务时，裁剪范围并在日志中声明
   裁剪，绝不把收尾动作压到预算尾部；可裁剪的旁支核验一律让位于
   「输出与收尾协议」的三步
7. **后台任务收割令**：收尾阶段不得等待任何后台/委派任务（审查、子代理、
   异步作业）。委派出去的工作必须 await 收割其结果后才能进入收尾；
   预算内收割不完的，在日志记为「未收割」并放弃——不得以等待换取
   完整性（历史死因：全部工作已完成并提交，末尾等待后台审查任务
   耗尽预算，ARTIFACT 行未落地）

## 修复轮（`$ISSUE_DIR/ralph-todo.md` 存在且非空时）

本轮不重跑 plan 全量任务，只消化清单：逐条修复、跑该条目的验收命令、
在清单中勾掉该条；全部消化后执行纪律 4（final_gate + 刷新
tests-output.txt 含 -v 证据）与纪律 5（提交）。执行日志以
「## 修复轮 N」为题**追加**到 `$ISSUE_DIR/implement.md`，不重写既有内容。

## 输出与收尾协议

执行日志用 write 工具**增量**写入 `$ISSUE_DIR/implement.md`：每任务一节
（改动文件、verify 命令与结果、跳过/blocked/裁剪/未收割说明），末尾附
final_gate 结果摘要。不要把日志写作堆积到收尾一次性完成——增量落盘的
日志在节点死亡后仍是失败诊断与下轮回流的输入。

收尾三步，顺序不可换、紧凑执行：

1. 提交全部改动（纪律 5；已提交的成果可被失败链 salvage 回收）
2. 日志落盘（含裁剪/未收割/blocked 说明）
3. stdout 最后一行输出：`ARTIFACT: $ISSUE_DIR/implement.md`

> 产物声明是节点的唯一存活信号：工作全部完成但 ARTIFACT 行未落地 =
> 节点失败、整轮作废。宁可裁剪范围、宁可放弃未收割任务，不可晚声明。
